# FinWise

FinWise is a manual personal finance tracker. People can add accounts and transactions, plan category budgets, view a clear monthly dashboard, export records, and delete their account. A public demo creates a separate short-lived sample space for each visitor.

The MVP code is in the [GitHub repository](https://github.com/callbyIshant/finWise). The [architecture and release gates](docs/MVP_ARCHITECTURE.md) describe the product decisions and remaining checks before a public launch. The earlier `finwise-project-spec.md` and root `frontend/` prototype files are retained for reference; the running application serves only `frontend/mvp/`.

## Stack

- Python 3.12 and FastAPI, SQLAlchemy, Alembic
- Neon Postgres for production (`DATABASE_URL` pooled; `MIGRATION_DATABASE_URL` direct)
- Semantic HTML, CSS, and vanilla JavaScript
- One Render Python web service serving both the UI and `/api/v1` from the same origin
- Argon2id password hashes, server-side sessions, `HttpOnly` cookies, CSRF protection, owner-scoped records

## Run locally

From PowerShell:

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
Copy-Item .env.example .env
# Edit SESSION_SECRET in .env before using real data.
alembic upgrade head
uvicorn app.main:app --reload --port 8000
```

Open `http://localhost:8000`. The default local database is SQLite for development only. The production database is Neon Postgres. Do not run the legacy `frontend/index.html` directly; it belongs to the retired prototype UI.

Run tests from `backend/`:

```powershell
pytest -q
```

## Production configuration

The [live free preview](https://finwise-c2rb.onrender.com) runs as one Python web service on Render in Singapore. Its configuration is captured in [`render.yaml`](render.yaml); the current service was created directly in Render, so future Blueprint changes must be applied to the service explicitly. [Render reserves pre-deploy commands for paid web services](https://render.com/docs/deploys). Test each migration on a disposable Neon branch, then run it separately against the default branch before manually deploying the web service. Automatic deploys are off. The schema owner's direct URL stays outside Render. The service uses these variables:

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Pooled Neon Postgres URL with TLS (`sslmode=require`) |
| `SESSION_SECRET` | Generated by Render; retain it across deploys |
| `PUBLIC_ORIGIN` | Final `https://...` site URL |

`APP_ENV=production` rejects startup if required security settings are missing. Password reset is unavailable in this preview, as requested; the sign-in page states this and `/reset` returns to sign-in. Account holders must retain their passwords. A public release needs a reviewed recovery flow. [Render Free is intended for previews rather than production](https://render.com/docs/free). Use separate Neon branches and credentials for migration checks. The Render runtime role should have only the data permissions it needs. See [Render's Blueprint reference](https://render.com/docs/blueprint-spec) and [Neon's pooling guidance](https://neon.com/docs/connect/connection-pooling).

The FinWise Neon project is `nameless-base-81278398` in Singapore. Migrations passed on an isolated branch and the default branch; a production-mode API smoke test passed with a limited runtime role and deleted its test data. Render deployed commit `030f5a6` successfully. The public release gates remain. Keep the direct migration URL and all passwords out of Git and Render's runtime environment.

## Core API

| Area | Routes |
|---|---|
| Auth | `/api/v1/auth/register`, `login`, `logout`, `csrf`; password reset is inactive in this preview |
| Profile | `/api/v1/me`, `/api/v1/me/preferences` |
| Accounts and categories | `/api/v1/accounts`, `/api/v1/categories` |
| Transactions | `/api/v1/transactions`, `/api/v1/transactions/export.csv` |
| Budgets and dashboard | `/api/v1/budgets`, `/api/v1/dashboard` |
| Demo | `/api/v1/demo/session` |

Interactive API docs are available at `/docs` only outside production. Private routes require a session cookie. State-changing routes require a session-bound CSRF token and same-origin request.
