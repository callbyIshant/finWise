# FinWise

FinWise is a manual personal finance tracker. People can add accounts and transactions, plan category budgets, view a clear monthly dashboard, export records, and delete their account. A public demo creates a separate short-lived sample space for each visitor.

The current MVP runs locally. The [architecture and release gates](docs/MVP_ARCHITECTURE.md) describe the product decisions and the remaining checks before a public launch. The earlier `finwise-project-spec.md` and root `frontend/` prototype files are retained for reference; the running application serves only `frontend/mvp/`.

## Stack

- Python 3.12 and FastAPI, SQLAlchemy, Alembic
- Neon Postgres for production (`DATABASE_URL` pooled; `MIGRATION_DATABASE_URL` direct)
- Semantic HTML, CSS, and vanilla JavaScript
- One Render Python web service serving both the UI and `/api/v1` from the same origin
- Argon2id password hashes, server-side sessions, `HttpOnly` cookies, CSRF protection, owner-scoped records

## Run locally

From PowerShell:

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
Copy-Item .env.example .env
# Edit SESSION_SECRET in .env before using real data.
alembic upgrade head
uvicorn app.main:app --reload --port 8000
```

Open `http://localhost:8000`. The default local database is SQLite for development only. The production database is Neon Postgres. Do not run the legacy `frontend/index.html` directly; it belongs to the retired prototype UI.

Run tests from `backend/`:

```powershell
pytest -q
```

## Production configuration

The [`render.yaml`](render.yaml) Blueprint defines one Python web service on Render's smallest paid compute plan. [Render reserves pre-deploy commands for paid web services](https://render.com/docs/deploys), so this plan is required for the migration step. The blueprint has not been applied and incurs no cost until you create the service. Set these variables in the Render Dashboard before deploying:

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Pooled Neon Postgres URL with TLS (`sslmode=require`) |
| `MIGRATION_DATABASE_URL` | Direct Neon URL for Alembic, with TLS |
| `SESSION_SECRET` | Generated by Render; retain it across deploys |
| `PUBLIC_ORIGIN` | Final `https://...` site URL |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM` | Transactional SMTP for password-reset links |

`APP_ENV=production` rejects startup if required security settings are missing. Automatic deploys are off while release checks are in progress. The Blueprint runs Alembic before the web process starts. Use separate Neon branches and credentials for development and production, and test migrations on a disposable branch first. See [Render's Blueprint reference](https://render.com/docs/blueprint-spec) and [Neon's pooling guidance](https://neon.com/docs/connect/connection-pooling).

The repository currently has no Git remote or connected Neon/Render project in this workspace. The MVP has **not** been deployed or verified against a live Neon database. Provisioning credentials, testing a Neon branch, configuring email, and the public release gates remain before launch.

## Core API

| Area | Routes |
|---|---|
| Auth | `/api/v1/auth/register`, `login`, `logout`, `csrf`, password reset |
| Profile | `/api/v1/me`, `/api/v1/me/preferences` |
| Accounts and categories | `/api/v1/accounts`, `/api/v1/categories` |
| Transactions | `/api/v1/transactions`, `/api/v1/transactions/export.csv` |
| Budgets and dashboard | `/api/v1/budgets`, `/api/v1/dashboard` |
| Demo | `/api/v1/demo/session` |

Interactive API docs are available at `/docs` only outside production. Private routes require a session cookie. State-changing routes require a session-bound CSRF token and same-origin request.
